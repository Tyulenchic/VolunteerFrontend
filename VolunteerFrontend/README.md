# Волонтёры ПМР — фронтенд

Одностраничное приложение (React 19 + TypeScript + Vite + Tailwind) для платформы волонтёров. Серверная часть — отдельный проект **VolunteerAPI** (ASP.NET Core); её контракт описан в `docs/05-api-contract.md` того репозитория и является источником истины. Файл `API_DOCUMENTATION.md` здесь — справочная копия для фронтенда, при расхождении верьте бэкенду.

## Быстрый старт

```bash
npm install
cp .env.example .env      # VITE_API_URL — публичный адрес API (не секрет, попадает в сборку)
npm run dev               # http://localhost:3000, прокси /api -> https://localhost:7227 (vite.config.ts)
npm run typecheck         # tsc без emit
npm run lint              # eslint (eslint.config.js); ошибок нет, предупреждения — на доработку
npm test                  # vitest (jsdom)
npm run build             # tsc -b && vite build -> dist/
```

В production-сборке `VITE_API_URL` обязателен (`src/config.ts` падает при его отсутствии). Деплой — GitHub Pages (`.github/workflows/deploy.yml`: тесты → проверка `VITE_API_URL` → сборка). Роутер — `HashRouter`, поэтому ссылки вида `/#/events/...` работают на статическом хостинге.

## Структура `src/`

| Каталог | Назначение |
|---|---|
| `api/` | Один модуль на группу эндпоинтов (`events.ts`, `admin.ts`, `organizer.ts`, …) поверх `client.ts` (axios: подстановка Bearer, одиночный повтор после refresh, лог ошибок с `traceId`) |
| `auth/session.ts` | Единственное место, где читаются/пишутся токены и выполняется refresh |
| `context/` | `AuthContext`, `NotificationContext` (тосты), `FeedbackContext`, `SiteContentContext` (редактируемые тексты сайта) |
| `components/` | Общие компоненты; `ui/` — примитивы админки/кабинета, `afisha/` — публичная «афиша», `notifications/`, `organizations/`, `profile/`, `admin/` |
| `pages/` | Страницы по разделам: публичные, `profile/`, `feed/`, `organizer/` (кабинет организатора), `admin/` |
| `content/` | Тексты по умолчанию (политика, правила, FAQ, «О нас») и реестр ключей `SiteContent` |
| `types/` | Типы DTO бэкенда |
| `hooks/`, `utils/` | Хуки списков/диалогов/ошибок и чистые утилиты (с тестами рядом) |
| `test/` | Общие помощники тестов (`render.tsx`, `fakeServer.ts`) |
| `assets/` | Только то, что реально импортируется (фоны — WebP) |

Вне `src/`: `docs/design/` — исходные макеты и архив черновиков (`docs/design/archive/`, в сборку не входят), `scripts/` — импорт/экспорт организаций (`organizations.seed.json`), `public/` — иконки.

## Что важно знать

- **Загрузка по требованию.** Страницы подключаются через `React.lazy` в `App.tsx`; каркас (layout, провайдеры, охранники маршрутов) загружается сразу. Первый заход скачивает ~100 КБ gzip вместо всего приложения. Новую страницу добавляйте тем же способом: `const XPage = lazy(() => import('./pages/…').then(m => ({ default: m.XPage })));`.
- **Токены и cookie.** Сайт **не использует cookie**. Токены доступа и обновления лежат в `localStorage` (ключи `accessToken`, `refreshToken`) и описаны только в `auth/session.ts`; там же ещё хранятся пара настроек интерфейса (вид списка мероприятий, свёрнутое меню админки). Поскольку это необходимое хранилище без аналитики и рекламы, баннер согласия не нужен и удалён; описание — в разделе 7 политики конфиденциальности (`content/defaults.ts`). Если токены когда-нибудь переедут в HttpOnly-cookie (потребует изменений бэкенда), баннер и текст политики нужно будет пересмотреть.
- **Заявки волонтёров.** Статусы: `Pending`, `Approved`, `Rejected`, `AttendanceConfirmed` и `Withdrawn` (волонтёр отозвал заявку). Отозванная заявка остаётся в списках организатора, администратора и самого волонтёра вместе с его комментарием (`withdrawalReason`); для кнопок «Подать заявку» она считается отсутствующей (повторная подача возобновляет ту же запись). Отзыв и отказ от участия идут через диалог `CancelParticipationDialog` → `POST /api/participations/{id}/cancel` с необязательной причиной.
- **Теги мероприятий** приходят в `EventResponseDto.tags`; поиск по строке находит и по тегам (ведущий `#` игнорируется).
- **Категории новостей** — свободный текст из админки; фильтры на странице новостей строятся из категорий загруженных новостей.
- **Опрос уведомлений.** Колокольчики запрашивают счётчик раз в 60 с и только пока вкладка видима.
- **Изображения** приходят относительными адресами (`/api/images/…`); `utils/imageUrl.ts` дополняет их адресом API, а `SecureImage` подгружает защищённые превью с токеном.
- **Ошибки.** `ErrorBoundary` + глобальные обработчики в `main.tsx`; ошибки API нормализуются в `utils/apiError.ts` и `hooks/useApiError.ts`.

## Известные пробелы

- ESLint настроен (`eslint.config.js`), но правила React-хуков про `setState` в `useEffect` оставлены предупреждениями (~70): в CI линтер пока не подключён.
- Логотип: `src/assets/logo.webp` (полный) и `logo-mark.webp` (знак для шапки/подвала); исходник — `docs/design/img/logo.png`. Иконки сайта — `public/favicon.png`, `apple-touch-icon.png`.
- Страницы `EventsPage` и `MyFeedPage` подгружают до 100 мероприятий за раз без догрузки по прокрутке.
- Тесты покрывают авторизацию, формы входа/регистрации, утилиты и кадрирование; страницы заявок, кабинета организатора и админки автотестами не покрыты.
